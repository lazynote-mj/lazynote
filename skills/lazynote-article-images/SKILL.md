# Lazynote Article Images

글이 독자에게 이해시키려는 관계를 시각화한다. 본문 시각자료는 논증을 압축하거나 비교를 쉽게 만들어야 한다. 표지와 썸네일은 글의 질문을 시각적으로 제시하되 본문보다 큰 약속을 하지 않는다.

## 원고와 사용 위치부터 읽는다

- 최신 원고와 `AGENTS.md`, `CONTEXT.md`, 시각자료·편집 지침, 기존 `images/`를 확인한다. 제목만 보고 그림을 정하지 않는다.
- 중심 질문, 이미지가 맡을 설명, 들어갈 위치, 그 위치까지 소개된 개념을 파악한다. 본문 이미지는 해당 절 앞뒤 문단도 읽는다.
- 연재라면 인접 편의 이미지에서 색·서체·정보 밀도를 확인한다. 같은 형식을 반복하기 위해 각 글의 다른 논증을 같은 틀에 끼워 넣지 않는다.
- 원고와 용도가 충분하면 바로 제작한다. 원고가 없고 제목만 있으면 표지의 가설적 콘셉트까지 만들 수 있지만, 수치·인과 도표를 확정하지 않는다. 결정에 필수적인 자료만 짧게 요청한다.

`references/editorial-basis.md`에는 「좋아하는 것들의 경제」에서 확인한 기준·사례와 새로 제안한 기본값을 구분해 두었다. 이 연재를 작업하거나 별도 스타일 지침이 없을 때 읽는다. 다른 프로젝트의 명시적 요구를 우선한다.

## 역할에 따라 제작 방식을 고른다

| 이미지의 역할 | 적합한 형식과 제작 경로 |
| --- | --- |
| 단계·갈래·주체·기록 경로를 설명 | 직접 제작한 SVG 개념도·구조도와 업로드용 PNG |
| 검증된 숫자와 추이를 비교 | 실제 데이터로 그린 차트와 편집 가능한 원본·업로드 파일 |
| 표지·썸네일·본문의 장면 또는 시각적 비유 | 사용 가능한 이미지 생성 도구로 제작한 일러스트 |
| 실제 사건·제품·화면 자체가 근거 | 확인된 원자료를 사용하거나 원문 링크 제공. 생성 이미지로 증거를 대신하지 않음 |

정확한 한국어 레이블·수치·축·화살표가 핵심이면 생성 모델에 전체 도표를 맡기지 않는다. AI 이미지는 배경이나 비유적 장면에 쓰고, 정확한 텍스트는 필요한 경우 별도 편집으로 배치한다. 사용자가 특정 방식의 제작을 지정하면 그 요청을 따르면서 정확성을 검수한다.

사용자가 ‘도표’를 요청했더라도 앞뒤 맥락과 기존 발행글이 본문 이미지라면 복사 가능한 텍스트 표만으로 완료하지 않는다. 기존 이미지의 실제 형태를 확인하고 삽입 가능한 시각자료로 제작한다.

## 도표·차트의 편집 기준

- 사실·논리 검증을 마친 내용만 도식화한다. 단위, 기간, 범위, 수치 출처를 원고와 맞춘다. 없는 값은 보간하거나 만들어 넣지 않는다.
- 화살표의 뜻을 분명히 한다. 시간 순서, 거래, 정보 이동, 조건부 가능성을 모두 자동적인 인과로 그리지 않는다. 가능성·한계·조건을 그림에도 남긴다.
- 아직 해당 위치에서 설명하지 않은 개념을 먼저 그리지 않는다. 뒤 절의 결론을 캡션으로 앞당기지 않는다.
- 같은 사람이 오갈 수 있는 활동을 서로 배타적인 사람 유형으로 나누지 않는다. 각자 시청·현장 응원·온라인 교류처럼 겹치고 이어지는 활동은 공통 주체와 연결을 표현하되 고정된 발전 단계나 필수 순서로 그리지 않는다.
- 비교 항목은 같은 기준으로 배치한다. 관계자산과 회계상 자산처럼 다른 개념을 하나로 합치지 않는다.
- 제목은 이미지가 실제로 설명하는 내용과 맞춘다. 출처와 기준일은 짧게 표시하되 읽히지 않을 만큼 줄이지 않는다.
- 모바일에서 읽기 어려우면 정보를 덜거나 그림을 나눈다. 색만으로 구분하지 말고 레이블·배치도 함께 사용한다.

## AI 이미지의 기획과 생성

다음은 기존 도표 기준을 생성 이미지로 확장한 운영 지침이다. 특정 화풍이 과거에 확정됐다고 가정하지 않는다.

1. 글의 핵심 긴장이나 전환을 한 장면으로 옮긴다. ‘투자=동전 더미’, ‘AI=로봇’ 같은 소재 아이콘만으로 글을 대체하지 않는다. 비유가 글에서 무엇에 대응하는지 한 문장으로 설명할 수 있어야 한다.
2. 프롬프트에는 용도와 비율, 전달할 의미, 구체적 장면·주체·행동, 구도, 스타일·색감, 텍스트 여부, 반드시 보존할 것과 피할 오해를 담는다. 원고 전체를 무작정 붙여넣지 않는다.
3. 확정된 참고 이미지가 있으면 실제로 열어 확인하고 도구에 참조로 전달한다. 경로만 적어 놓고 모델이 이미지를 보았다고 가정하지 않는다.
4. 환경에 이미지 생성 도구가 있으면 그 도구의 안내에 맞춰 생성한다. 관련 `imagegen` 스킬이 제공되는 환경에서는 실행 절차를 읽어 따른다. 없는 도구·모델·API 키를 전제로 하지 않는다. 도구가 없으면 재사용 가능한 프롬프트와 제작 사양을 제공하고 실제 이미지가 아직 생성되지 않았음을 밝힌다.
5. 생성 결과를 직접 확인한다. 콘셉트가 원고와 어긋나거나 글자·형태가 깨졌다면 문제를 특정해 수정한다. 요청과 검수 기준을 충족하면 끝내고, 취향 차이만으로 재생성을 반복하지 않는다. 도구 실패나 해결되지 않는 오류는 한계와 함께 알린다.

텍스트 삽입 요청이 없으면 표지·썸네일용 생성 이미지 자체에는 글자를 넣지 않는 것을 제안 기본값으로 삼는다. 제목이 따로 올라갈 때는 여백과 잘림을 고려한다. 사실적인 장면도 실제 촬영 자료처럼 설명하지 않고, 캡션이 필요하면 ‘AI 생성 개념 이미지’ 등 제작 성격을 밝힌다.

## 외부 자료

외부 사진·캐릭터·스틸·화면을 가져와 쓰려면 프로젝트의 이용허락 기준을 확인한다. 출처 표기만으로 허락을 대신하지 않는다. 사용할 근거가 확인되지 않으면 원문 링크 또는 직접 제작한 설명 이미지로 처리한다. AI로 다시 그렸다는 이유만으로 특정 원본의 복제 문제가 해결됐다고 간주하지 않는다.

## 저장과 최종 확인

프로젝트의 기존 구조를 우선하고, 없으면 아티클 폴더의 `images/`에 내용을 드러내는 이름으로 저장한다. 직접 제작 도표는 SVG 원본과 PNG를, 생성 이미지는 실제 결과 파일과 재사용할 최종 프롬프트·참조 정보를 남긴다. 파일명만 바꿔 SVG 원본이 있다고 주장하지 않는다.

이미지와 함께 삽입 위치, 짧은 캡션(필요한 경우), 실제 그림을 설명하는 alt를 준비한다. 원고 삽입까지 요청받았다면 프로젝트가 정한 원고 동기화 규칙을 적용한다. 이미지 제작 요청만으로 발행하거나 외부 계정에 업로드하지 않는다.

전달 전 다음을 실제 결과물과 대조한다.

- 최신 원고의 용어·숫자·조건·화살표 의미와 일치하는가?
- 삽입 위치의 앞뒤 논리와 캡션·alt가 일치하는가?
- 한글, 숫자, 화살표 끝, 줄바꿈, 경계가 깨지거나 겹치지 않는가?
- 게시될 크기나 모바일 폭으로 보아도 핵심 관계를 읽을 수 있는가?
- 원본·업로드 파일이 열리며, 저장 경로와 본문의 이미지 링크가 맞는가?

본문 수정으로 단계·조건·수치가 달라지면 기존 이미지와 캡션도 다시 확인한다. 최종 응답에는 실제 이미지 미리보기 또는 파일 링크와 맡긴 역할을 짧게 전달한다.
