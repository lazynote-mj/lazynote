# 기획 인터뷰

시리즈나 책의 목적·독자·용어·전체 목차가 저장소 어디에도 없을 때 쓴다. `SKILL.md`의 「시작 전에」 표를 다시 확인해도 없으면 여기로 온다.

## 언제, 얼마나 하는가

**전부 없으면** 아래 순서대로 처음부터 인터뷰한다. **일부만 없으면** 있는 문서·절은 그대로 두고 없는 질문만 묻는다 — 저장소를 먼저 읽고 이미 답이 있는 항목은 건너뛴다.

**사례 인벤토리처럼 스킬마다 있는 축적형 산출물은 여기서 만들지 않는다.** 글이 서너 편 쌓이기 전에는 만들 대상이 없다.

## 질문 순서

큰 그림에서 세부로 좁힌다. 순서를 바꾸면 앞 질문의 답이 뒤 질문의 전제가 되는 자리에서 다시 물어야 한다.

### 1. 정체성 — README 상단

- 무엇에 대한 시리즈/책인가. 한 줄로 답할 수 있는가
- 이 시리즈가 답하려는 큰 질문은 무엇인가
- 전작이나 관련 작업과의 관계가 있는가. 있으면 무엇을 이어받고 무엇을 다르게 다루는가

### 2. 타깃 독자 — README 또는 CONTEXT의 독자 정의

- 누구를 위한 글인가 (직무·역할·조직 규모·관심사 등 구체적으로)
- 독자가 이미 안다고 가정할 수 있는 것은 무엇인가
- 처음부터 설명해야 하는 것은 무엇인가

**「쉽게 쓴다」의 기준점이 여기서 나온다.** 이 답 없이는 어디까지 설명할지 매 편 다시 판단해야 한다.

### 3. 관점의 규칙 — CONTEXT의 관점의 규칙 / 쓰지 않는 언어

- 이 시리즈가 **아닌** 것은 무엇인가. 인접 주제와 헷갈리기 쉬운 지점이 있는가
- 흔히 빠지는 함정이 있는가 (예: 기술 성능 얘기로 흐르는 것, 특정 회사의 제품 언어를 보편 개념처럼 쓰는 것)
- 문체나 톤에 분명한 선호가 있는가 (있으면 `docs/voice-guide.md`로, 없으면 만들지 않는다 — 호출한 스킬의 기본 문체 기준을 따른다)
- 사례 운용에 프로젝트 특유의 방침이 있는가 (예: 특정 업계 이해관계자 다루는 방식). 일반 원칙은 호출한 스킬의 참고 문서(예: `lazynote-case-writing`의 `references/sourcing.md`)가 이미 다루므로, **거기서 벗어나는 것만** 여기 적는다

### 4. 핵심 개념 — CONTEXT의 중심 개념(용어집 시드)

- 시리즈를 관통하는 핵심 개념이 있는가. 3~7개 선에서 시작한다
- 각 개념의 정의와, 헷갈리기 쉬운 유사 개념과의 구분
- 피하기로 한 동의어가 있는가

용어집은 여기서 완성하지 않는다. 글이 쌓이며 항목이 늘어나는 문서다 — 시작점만 만든다.

### 5. 전체 구성 — README의 시리즈 구성(목차)

- 몇 편/몇 장 정도로 예상하는가. 모르면 대략적인 규모만
- 부/파트로 나뉘는가. 나뉜다면 각 파트가 답하는 질문은 무엇인가
- 각 편(적어도 다음에 쓸 몇 편)이 다룰 핵심 질문은 무엇인가. 제목까지 확정할 필요는 없다

### 6. 아티클 공통 구조 — README의 아티클 기본 구성

- 매 편이 따를 공통 흐름이 있는가 (예: 현상/질문 → 기존 방식의 한계 → 구조적 변화 → 사례 → 프레임워크 → 시사점 → 다음 질문)
- 매 편이 독자에게 남겨야 할 것이 있는가 (개념·프레임워크·체크리스트 등)

### 7. 형식 제약 — README

- 발행처(브런치·블로그·뉴스레터 등)
- 목표 분량
- 발행 주기나 마감이 있는가

## 목차의 확정성

**확정이 아니라 현재 시점의 최선의 추정치다.** 저자가 전체를 다 모르면 부/파트 수준의 로드맵만 잡아도 된다. 모르는 부분은 `미정 — n편 이후 결정`처럼 **비어 있다고 명시**한다 — 그럴듯하게 채우지 않는다.

다만 **조사(1단계)로 넘어가려면 최소한 다음에 쓸 편이 답할 질문까지는 있어야 한다.** 그게 없으면 조사가 무엇을 찾아야 하는지 모른 채 시작한다.

목차는 글이 쌓이며 갱신된다. 사례 인벤토리와 같은 성격이다 — 처음에 완성하는 문서가 아니라 계속 고쳐 쓰는 문서다.

## 완료 조건

전부 채워야 인터뷰가 끝나는 게 아니다. 아래 세 가지가 있으면 조사로 넘어간다.

1. 목적과 타깃 독자
2. 다음에 쓸 편이 답할 질문
3. 핵심 개념 몇 개(0개여도 되는 시리즈가 있다 — 모든 시리즈가 고유 개념을 필요로 하지는 않는다)

나머지(전체 목차의 뒷부분, 문체 지침, 사례 운용 방침 등)는 있으면 좋지만 없어도 첫 편 조사를 막지 않는다.

## 추측 금지

**저자 답변에 없는 내용을 그럴듯하게 채우지 않는다.** 인터뷰의 존재 이유가 추측을 막는 것이므로, 여기서 지어내면 인터뷰를 한 의미가 없어진다. 질문에 답이 안 나오면 다시 묻거나 비워 둔다.

## 저장 전 확인

초안을 만들었으면 저자에게 보여주고 승인받은 뒤에 파일에 쓴다. 기존 문서가 일부 있으면 있는 내용은 건드리지 않고 빈 자리만 채운다.

```markdown
**{한 줄 정의 — 이 시리즈가 다루는 것}**

{전작·관련 작업과의 관계. 없으면 이 문단 생략}

## 시리즈 구성

**Part 1. {파트 제목}**
1. {편 제목 또는 다룰 질문}
2. {편 제목 또는 다룰 질문}
...

## 아티클 기본 구성

각 편은 아래 흐름을 기본으로 한다.

{공통 흐름 단계 → 화살표로 연결}

{매 편이 남겨야 할 것}

## 형식

발행처: {}
목표 분량: {}
발행 주기: {}
```
